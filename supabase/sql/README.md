# Настройка Supabase

SQL-скрипты предназначены для последовательного запуска в Supabase
Dashboard через раздел SQL Editor.

## Предварительные требования

В схеме `public` должна существовать таблица `profiles` со столбцами:

- `id` типа `uuid`, связанным с `auth.users.id`;
- `username` типа `text`.

## Порядок запуска

### 1. Настройка профилей и приглашений

Выполните `01_invite_registration.sql`.

Скрипт:

- добавляет в `profiles` email, роль и данные о приглашении;
- генерирует существующим профилям уникальные пригласительные коды;
- настраивает автоматическую генерацию кода для новых профилей;
- проверяет пригласительный код при регистрации;
- сохраняет пользователя, который выдал приглашение;
- создаёт профиль после добавления пользователя в `auth.users`.

Пригласительные коды многоразовые.

### 2. Создание администратора

Откройте `02_bootstrap_admin.sql` и замените значения:

```sql
ADMIN_EMAIL
ADMIN_USERNAME
ADMIN_PASSWORD
```

Подставляйте реальные данные только в SQL Editor. Не сохраняйте пароль
администратора в файле и не коммитьте его в Git.

После выполнения скрипт выведет профиль администратора и его
пригласительный код. Если пользователь с указанным email уже существует,
его профиль будет обновлён и получит роль `admin`.

### 3. Настройка проверки регистрации

Выполните `03_signup_validation_hook.sql`.

Затем откройте в Supabase Dashboard раздел Authentication → Hooks,
выберите `Before User Created`, укажите Postgres-функцию
`public.hook_validate_signup` и сохраните настройку.

Hook возвращает понятные ошибки:

- `Email уже занят`;
- `Имя пользователя уже занято`;
- `Код приглашения недействителен`.

Доступ к данным профилей для проверки получает только внутренняя роль
Supabase Auth `supabase_auth_admin`. Роли `anon` и `authenticated` не могут
вызывать hook напрямую.

## Проверка

После настройки проверьте регистрацию в трёх сценариях:

1. существующий email;
2. существующее имя пользователя;
3. недействительный пригласительный код.

После этого зарегистрируйте пользователя с уникальными данными и действующим
кодом. В `public.profiles` у него должны появиться собственный `invite_code`
и ссылка `invited_by` на пригласившего пользователя.
